# Scene correction: control the granularity

Reference example: `cases/pantry/` (correction records and acceptance results) and its `CHANGELOG.txt` (how to write version notes).

## 1. Smallest unit of change = one object × the fields you have evidence for

- **Write only fields that are actually wrong.** If an object's `x` is wrong, write `x` only. Do not copy the whole automatic record and edit one number.
- **One change fixes one problem.** If several objects share a problem, each still gets its own entry with its own evidence.
- **Dependencies between objects belong in code.** For example, when a shortened cabinet changes a neighbouring surface, handle that in `geometry/apply_measured.py`. Do not hand-sync a second place in JSON.
- **Shape problems are fixed in that object's program** (`hand_objects/<id>/program.py`). Parameters that come from the scene go in the object's `hand_params`, not hard-coded.

## 2. Which file (keep problem types separate)

| Problem | File | Format |
|---|---|---|
| Automatic position or size is wrong | `measured/pose_overrides.json` | `{"<id>": {only the changed fields, "_why": "..."}}` |
| Automatic stage missed an object | `measured/extra_objects.json` | Add a complete entry to `objects[]` (id/x/y/z/yaw_deg/dims/mount/category/`why`) |
| Architecture the wall fit cannot express (columns, wall bumps, sockets, trims) | `measured/room_features.json` | One entry per feature in `features[]`: `name/lo/hi/material/surface/why` |
| Object switched to a hand-written model | `measured/blend_overrides.json` | `"<id>": "runtime/outputs/hand/<id>/<id>.blend"` |
| Per-frame camera drift | `geometry/camera_refine.json` | Generated by `geometry/refine_cameras.py` only; never hand-edited |
| Planar position refinement | `geometry/pose_refine.json` | Generated by `geometry/refine_poses.py` only. Copy an entry into `pose_overrides` only if it has `accept: true`. |

`runtime/` is not version-controlled. After a change, sync the files back to `cases/<scene>/`. To reuse them, copy from there into `runtime/video/<scene>/`.

## 3. Every change carries evidence (`_why` / `why`)

Write evidence that someone else can re-check. It must include at least one observation they can locate:

- **A point-cloud slice:** the axis, the height range and the value read.
- **A video time or frame.**
- **A before/after metric from an automatic method** (for example, IoU over N views).
- **The date of the check.**
- **What was wrong before**, not just the new value.

"Looks better", "by eye" and "tweaked" are not evidence.

## 4. Acceptance thresholds

- **Silhouette-fit translations** are accepted only if the mean IoU improves by more than the threshold in `refine_poses.py`. Below it, keep `accept: false` and do not copy the fit by hand.
- **Fits that would collide** with architecture or another object are **clamped** to the nearest collision-free position. Record the original fit and the reason in `_why`.
- **Origin and resting height.** The origin is at the centre of the bottom face. An object on a counter has `z` equal to the counter height: neither sunk nor floating.
- **Joints have one degree of freedom.** The axis must sit on the real hinge edge, valve core or bottle neck.

## 5. Acceptance after every change (all must pass)

```bash
python geometry/apply_measured.py runtime/video/<scene>                     # rewrite measured/scene_plan.json
python hand_objects/build.py <only the ids whose geometry changed>
# after reassembling the scene:
blender -b runtime/video/<scene>/measured/scene/scene.blend --python geometry/clip_check.py -- runtime/video/<scene>
blender -b runtime/video/<scene>/measured/scene/scene.blend --python geometry/sim2real_audit.py -- runtime/video/<scene>
python -m pytest tests/
```

- **`clip_check.json`:**
  - all origins are ok, and every joint axis has the correct position and direction;
  - zero static clipping, and zero motion clipping at 25 / 50 / 75 / 100 % open;
  - intentional connections are the only exception, and each must be explained.
- **`sim2real_audit.json`:** `failures == 0`.
- **Compare with the previous version in `cases/<scene>/measured/`.** Objects you did not touch must give unchanged results. If they changed, the granularity is out of control: find out why first.
- **Visual check:** use `hand_objects/preview.py` to render from the video cameras. This is for checking only and is not delivered.

## 6. Versioning

Add a block at the top of `cases/<scene>/CHANGELOG.txt` in the existing format:
1. version and date;
2. what changed, listed per object as "was … → now …";
3. check results (clipping count, audit failures).

Write "geometry unchanged / results as previous version" for anything you did not change.
