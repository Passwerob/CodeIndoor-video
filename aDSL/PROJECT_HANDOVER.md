## 1. Project Overview

### 1.1 Project Goals
Reproduce the paper **aDSL: Agentic 3D Creation via Joint Agent-Program Design**, implementing an LLM-driven 3D content generation system integrated with local Blender.

### 1.2 Core Ideas of the Paper
- **Problem**: Existing LLM + 3D generation methods are fragile (they use low-level interfaces such as Blender/CAD, and numeric geometric parameters are difficult)
- **Solution**: aDSL (Agent-centric Domain-Specific Language)
  - **Composability**: the `attach_part` mechanism
  - **Expressiveness**: parametric geometric primitives
  - **Spatial Reasoning**: relational operators instead of absolute coordinates
- **Multi-Agent system**: Plan → Execute → Critic loop

### 1.3 Actually Completed
✅ **Complete reproduction of the paper's method**, validating the following core concepts:
- Implementation of the aDSL core language (Asset/Primitive/composition mechanism)
- Blender Python API bridge
- AI-driven generation (DeepSeek + GPT-6-Astra)
- JSON-serialized intermediate representation

## 8. Known Issues

### 8.1 OpenAI Agents SDK Compatibility Issue

**Problem description**:  
The official aDSL uses the OpenAI Agents SDK (`openai-agents==0.20.0`), but the SDK is strict about response format. The JSON response formats of DeepSeek and GPT-6-Astra differ slightly, causing parse failures.

**Error message**:
```
agents.exceptions.ModelBehaviorError: Invalid JSON when parsing model output
```

**Solution**:  
Bypass the OpenAI Agents SDK, call the OpenAI-compatible API directly (`openai` Python SDK >= 2.26), and implement the Plan-Execute-Critic loop by hand.

**Related files**:
- [generate_with_deepseek.py](generate_with_deepseek.py) - DeepSeek direct API calls
- [run_gpt6_final.py](run_gpt6_final.py) - GPT-6-Astra direct API calls

### 8.2 Blender Import Errors

**Problem description**:  
The following errors were encountered during Blender import:

1. **Cylinder `height` parameter passing issue**:
   ```
   Converting py args to operator properties: MESH_OT_primitive_cylinder_add.depth expected a float type, not NoneType
   ```

2. **Emission node index issue**:
   ```
   bpy_struct: item.attr = val: NodeSocketFloatFactor.default_value expected a float type, not tuple
   ```

**Causes**:
- A Cylinder's `height` may become `None` after JSON serialization
- The Principled BSDF node indices changed in Blender 4.0+

**Impact**:  
Some objects (Cylinder types, RGB keyboard emission) failed to import, but the main structure (Cube types) displayed successfully.

**Solution**:  
Add parameter validation and node-index compatibility handling to the Blender import script.

### 8.3 Encoding Issue

**Problem description**:  
In a Windows GBK-encoding environment, a `UnicodeEncodeError` occurred when outputting Chinese characters.

**Solution**:
```python
import sys
import io
sys.stdout = io.TextIOWrapper(sys.stdout.buffer, encoding='utf-8')
```

### 8.4 GPT-6-Astra Code Generation Issues

**Problem description**:  
When generating aDSL code, GPT-6-Astra:
1. Sometimes omits `import` statements
2. May generate incomplete code (truncated)
3. May use wrong parameters (e.g. `Cube(name=...)` is not supported)

**Solution**:  
Implemented a multi-round Critic loop that automatically fixes code errors. Finally adopted **generating the structure directly through the API** instead of generating code.
