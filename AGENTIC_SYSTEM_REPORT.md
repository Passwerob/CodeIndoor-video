## 1. Admission of error and changes

In the previous round I hand-wrote `part_programs.py` / `run_fine_sofa.py`. The renders looked good, but those were **modeling scripts I wrote myself**, not Agentic Coding. Both files have been physically deleted. The core aDSL representation (`Asset` / `component_id` / `asset_to_dict`) was **not changed**; it is used only as the carrier layer, and no further "verify aDSL" demo was made.

All geometry is now **generated by DeepSeek**:

```
ObjectPlan (upstream, unchanged)
  → Constructor Agent generates the Blender Python for the part
  → Static contract check (AST: build_part signature, import whitelist, network/file/scene-clearing forbidden)
  → Blender sandbox runs the program on its own (real modeling, vertex count check)
  → On failure: error + full code fed back to the Agent, which rewrites the whole program (execution-guided repair)
  → On success: source file registered in an aDSL ProgramComponent (file reference + sha256, never embed the code string)
  → Blender assembles all Agent programs → multi-view render
  → Visual Critic (deepseek-flash reads the render images) → feedback fed back → local regeneration → accept/rollback
```

New modules (all in `adsl_adapter/`):

| File | Responsibility |
|---|---|
| `agentic_coder.py` | Constructor Agent calls, AST contract check, Blender sandbox execution, error-feedback repair, LLM transport backoff retry |
| `part_runner.py` | Single-program sandbox inside Blender: runs `build_part`, stamps `adsl_component_id`, validates mesh vertices |
| `agentic_pipeline.py` | Orchestration + shared programs for symmetric groups + immutable baseline + aDSL ProgramComponent AST + Visual Critic |
| `run_agent_scene.py` | Inside Blender, executes only Agent-generated programs, lighting, 3 views before and after, local re-execution verification |
| `critic_repair.py` | Critic-feedback regeneration, paired shared programs, accept/rollback, baseline restore |
| `program_component.py` | Structured component (adds `source_path` / `source_sha256` provenance), pure data, no bpy |

11 calls rather than 15: the left and right armrests share one program, and the four legs share one program (each positioned via its own `params["origin"]`), which keeps symmetry and saves calls.

Problems the Critic pointed out (real, not glossed over): distorted geometry, a round coffee table/ring mixed into the seating area, seat cushions floating and overlapping, deformed and asymmetric armrests, and a confused frame-and-leg placement. **This is quality variance in LLM-generated geometry, not a pipeline fault.**

## 3. Facts actually observed over multiple runs

| Observation | Data |
|---|---|
| Agent first-pass rate | Best 15/15; worst 10/15 (affected by generation randomness + gating) |
| Critic score variance | **3–6 points** (same system, same brief) |
| Execution-guided repair **did trigger** | In one run two legs took 2 attempts each; in another there were 8 repairs; `use_auto_smooth` being removed in Blender 5.2 and duplicate face creation in `bmesh.faces.new` were both caught by the sandbox and fed back |
| LLM transport failure | `RemoteDisconnected` once caused a lost part → 3 backoff retries added |
| Critic-feedback regeneration | Ran end to end, and showed **regressions** such as 6→5 and 6→4 |
| Acceptance rollback | When the score dropped, the immutable baseline was restored automatically (really triggered several times) |
| Symmetric shared programs | Generating left and right independently produced different shapes → switched to sharing; that fix also saved 4 LLM calls |
| Baseline drift bug | Several runs backed up the "current state", so the rollback target drifted → changed to an immutable `generated_baseline/` baseline |

**One clear self-correction**: I added a "geometry AABB size hard gate" intended to block runaway giant elliptical discs, but it wrongly rejected chamfered/curved thin parts, dropping the pass rate from 15/15 to 10/15 and the Critic score to 3. I changed it to a **non-blocking warning** and wrote the reason in the code. The pass rate then recovered to 15/15. This was over-iteration, recorded honestly.

## 5. Still unsolved / to improve (honest)

1. **Unstable generation quality**: scores swing between 3 and 6, and the Agent will invent round tables/rings, floating wireframes and distorted armrests out of nothing. It needs a stronger generation contract, geometric plausibility hints, multi-round Planner/Checker, and a "keep the best historical version" mechanism (currently the baseline is the latest run, not the best run).
2. **Layout problems belong to the Planner layer**: the brief is two-seat, but the upstream ObjectPlan gave 3 seat_cushion / 3 back_cushion. The Critic repeatedly points out "three seats, not two". With per-stage SoT isolation, this should go back to **re-planning at generation time**, and cannot be fixed by locally editing armrests at edit time. At present `critic_repair.py` only records it as `layout_issues_deferred_to_planner` and **does not implement Planner feedback**.
3. **P2 dirty-flag closure / P4 RelationAssembly local re-solve / P5 three-way consistency** are still not implemented; for local edits the caller currently names the dirty components explicitly.
4. **A standalone environment (uv / Python 3.11 / Blender 4.4.3), PHASE 2 native SceneCode reproduction, and the full living-room PHASE 5** are still not done. This is currently standalone validation under local Blender 5.2.2 + the gateway, not the SceneCode pipeline running as-is.
5. The `generated/` directory still holds experimental `_attempt*.py` files from many rounds; `generated_baseline/` is the authoritative version.
